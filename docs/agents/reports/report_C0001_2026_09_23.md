## Work Performed

### 선행 분석과 독립성

[기능 inventory 및 실패 분석](../../design/legacy-analysis.md)을 구현 전에 작성했다.
기존 NOW/AMS/SD media/OTA/RTC/설정/버튼/네트워크와 오류 기록을 확인했다.
기존 origin `CXITRON/MILESTONE-NOVA`와 현재 작업 디렉터리를 신규 프로젝트로
사용하며, legacy 경로는 새 펌웨어의 include/link/build 입력에 들어가지 않는다.

계승한 개념은 AMS 수신, authoritative position 기준 보정, cache, 시간 기준 영상
frame 선택, 설정 검증, 비활성 OTA slot과 서명 검증이다. 새 해상도·핀맵·AHT10·
배터리 회로·전원 UX에 맞춰 구현을 새로 작성했다.

MAIN/ZERO/SAFE, inter-board SPI, 과거 GPIO/공유 SPI, `.inc` 전역 상태 공유,
legacy bundle/signing key, 과거 포맷 호환과 재부팅 기반 profile 전환은 도입하지
않았다. cache 폴더 재검색, BLE 객체 파괴와 callback의 경합, 오래된 시각으로 인한
false timeout 같은 기록을 새 설계의 소유권·고정 buffer·세대 검사에 반영했다.

### 모듈, 데이터 흐름과 수명

상세 설계는 [아키텍처](../../design/architecture.md), 데이터 형식은
[프로토콜](../../guides/protocol.md), GPIO 표는 [README](../../../README.md)에 있다.

- `board/Board.h`가 핀 정의의 단일 기준이다. 중복, 예약/flash/PSRAM 영역 사용을
  정적으로 검사한다. LCD FSPI와 SD HSPI를 분리했고 기본 clock은 각각 20/10 MHz다.
- Arduino loop가 UI/LCD, 앱 상태, 입력, 미디어 clock, I2C/ADC, LED와 NVS를 소유한다.
  별도 SD/OTA worker만 추가하며 core affinity를 강제하지 않는다.
- BLE callback은 bounded event queue로 전달한다. main loop에서 AMS/helper를
  파싱하고 MediaSession을 변경한다. 보안·연결·구독·광고에 timeout과 재시도를 둔다.
- NOW 흐름은 iOS AMS 또는 실제 JSON을 전달하는 helper → MediaSession → track key →
  local SD provider → artwork/가사 상태 → UI다. AMS가 제공하지 않는 artwork/lyrics는
  SD 파일이 실제 공급원이다. 수신되지 않은 metadata/position을 만들어내지 않는다.
- LRC는 provider/cache 경로, parser, binary-search timeline, renderer를 분리했다.
  `/lyrics/<16자리-key>.lrc`에 최대 32 KiB/512 entries를 받으며 UTF-8, 복수 timestamp,
  offset, 중복, malformed line, CRLF/LF, 빈 instrumental, unsynced를 처리한다.
- 재생 위치는 authoritative anchor와 monotonic 경과 시간으로 추정한다. pause와
  disconnect는 고정하고 seek는 즉시 보정하며 곡 변경 시 timeline/아트를 초기화한다.
  늦게 도착한 SD 결과는 generation을 비교해 폐기한다.
- PSRAM에 RGB565 canvas/직전 frame, 가사 pool 및 media buffer를 둔다. LCD는
  변경된 8행 strip만 전송하고 flush 중인 frame을 수정하지 않는다. 텍스트는 글꼴
  폭으로 줄을 나누고 영역 안에 clip한다. PSRAM 할당 실패는 headless/degraded로 처리한다.
- SD 결과 buffer는 consumer가 반환할 때까지 worker가 수정하지 않는다. 이미지/영상은
  160×160 raw RGB565와 CRC를 검사하고, 재생 시간이 늦으면 frame을 건너뛴다.
  사진은 한 번만 읽고, 손상 파일을 자동 반복 요청하지 않으며 끝난 영상은 다시 시작할 수 있다.
- AHT10 conversion과 LED 효과는 상태/시각으로 진행한다. RTC/센서/SD/무선 부재를
  재부팅 사유로 삼지 않는다. 배터리는 ADC 평균/필터/보정과 비선형 LUT를 사용한다.
- 설정은 schema/CRC/범위 검사와 기본값을 사용한다. credentials는 일반 설정과 분리한다.
  부팅 SD import의 우선순위와 NVS 저장 동작을 README에 명시했다.

### Deep Sleep와 OTA

OFF는 설정 저장 → OTA/BLE 종료 확인 → SD worker 반환/파일 종료 → Wi-Fi/LCD/
RGB/RED/GREEN/I2C 종료 → OK 해제 대기 → GPIO5 ext0 LOW wake 순서로 진행한다.
설정 저장 실패 시 정상 OFF 요청은 취소한다. wake 시 RTC pad를 복구하고 시작 시
눌린 버튼을 해제 전까지 억제한다. 다른 버튼을 wake source로 사용하지 않는다.

OTA는 사용자 활성화 10분 창, 별도 비밀번호/RSA 공개키, SDK의 RSA-PSS/SHA256
검증과 비활성 6 MiB slot을 사용한다. BLE를 정지한 상태로 worker가 수신하고
시간/무응답 제한, 오류/진행률 UI를 제공한다. private key는 firmware에 넣지 않는다.

설치된 SDK의 rollback 설정을 확인하고 `verifyRollbackLater()`를 명시적으로
구현했다. 새 이미지가 60초/500회 loop와 최소 heap 조건을 만족한 뒤 확정한다.
그 전의 reset은 bootloader rollback 대상이다. 이 경로의 실물 전원 차단 시험은
별도 검증이 필요하다.

## Issues / Limitations

- LCD 배선/색/방향/clock, 실제 SD read와 제거, 센서/ADC 보정, BLE pairing/
  reconnect, RF 공존, OTA 중단/rollback, deep sleep 전류, 24–72시간 soak는 미검증이다.
  [실물 점검표](../../guides/hardware-validation.md)에 절차와 상태를 기록했다.
- LeakSanitizer는 ptrace 환경에서 동작하지 않아 기본 비활성화했다. ASan/UBSan은 유효하다.
  지원 host에서는 `ASAN_OPTIONS=detect_leaks=1`로 실행할 수 있다.
- artwork/lyrics는 local SD가 공급원이며 온라인 서비스는 연결하지 않았다.
  Android 등의 native companion 앱과 모든 player API 통합을 포함하지 않으며 BLE relay를 제공한다.
- U8g2 korean2 미수록 문자는 `?`로 표시한다. 긴 AMS attribute는 notification 범위에서
  안전하게 처리하며 확장 attribute read는 미구현이다. unsynced 가사는 첫 4줄을 표시한다.
- 이전 MVJ/MSM/BMP 호환, AP 설정 portal, 환경 CSV 이력, 오디오 재생, SD hot-remount/
  index 실시간 재검색은 제공하지 않는다. RGB는 재생 상태 애니메이션이며 오디오 분석이 아니다.
- 배터리 잔량은 전압 기반 추정이다. LCD에 MISO가 없어 응답 확인이 불가능하다.
  Deep Sleep은 외부 전원의 물리 차단이 아니다. OTA의 SD 공개키 provisioning은
  secure boot를 대체하지 않는다.
