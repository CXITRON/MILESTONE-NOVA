## 추가 위험 후보 — 결함/실기 원인 확정 아님

### R01 SD 순회에서 명시적 양보가 빠진 경로

StorageFiles.cpp scan 백업/exists 루프 및 List의 continue 경로,
UploadChunk retry CRC 확인 루프에는 작업 시간 예산/양보가 없다.
nova-sd는 CPU0 priority1이며 SDK는 CPU0 idle을 5초 WDT로 감시한다.
많은 파일·느린 SD에서 영향을 측정해야 한다. 초기17 WDT의 실제 원인이라고
확정하지 않는다. 전체 카드 파일 수·단계 시간·idle 실행 기록으로 확인해야 한다.

### R02 8KiB JSON 길이 제한이 재귀 깊이를 제한하지 않음

Portal.cpp:17은 cJSON_Parse 전에 크기만 확인하고 task stack은 :84에서12KiB다.
설치된 SDK CONFIG_CJSON_NESTING_LIMIT=1000이며, 깊이1000의 배열은2001bytes로
본문 제한 안에 들어간다. cJSON 공식 문서도 중첩에 따른 stack overflow와 깊이 제한을
설명한다: https://github.com/DaveGamble/cJSON#deep-nesting-of-arrays-and-objects
스키마 검사 전에 파싱하므로 잘못된 AP 세션 입력의 stack budget 검사가 필요하다.
SDK의 실제 최소 실패 깊이는 실기/대상 stack 측정 전까지 미확정이다.
제안: 지원 스키마에 맞춘 얕은 depth/node 제한을 파싱 전 적용하고 string escape를 고려한다.

### R03 최신 릴리스 문자열의 공유 보호 범위

Firmware::latest(:41)는 mutex로 읽지만 check(:65,:122)의 url_/version_ 쓰기는
같은 mutex 밖에 있다. main의 Available 판단과 worker의 다음 check 시작이 겹치는
간격을 포함해 읽기/쓰기 소유권을 검토해야 한다. 잘못된 표시/UB 가능성의 정적 후보이며
이번 검토에서 실물 실패나 race sanitizer 재현을 얻지는 못했다.
