## Title

AP Sync 병목 개선: 비동기 LCD 이중 버퍼, 영상 렌더 융합, JPEGDEC 선택 경로

## Summary

Claude의 AP Sync 20 FPS 인계를 받아 LCD DMA·PSRAM 이중 버퍼, 영상 렌더 융합,
JPEGDEC 선택 경로와 작업 코어 배치를 구현했다. 현재 기기/소스는 candidate6 0.1.14다.
동일 19.1초 영상 두 재생 주기에서 후반의 원본 프레임 완료 속도는 18.2~18.6 FPS,
전체 6개 5초 구간은 16.5~18.6 FPS였다. 화면 전송 횟수는 17.1~20.3/s로 중복을 포함한다.
일률적인 원본 20 FPS 달성을 주장하지 않는다. 사용자가 “18~19면 충분할 것 같은데?”라고
기준을 정해 현 빌드에서 성능 최적화를 마무리했다. U0001 전체 완료 판단은 별도다.
미적용 후속 DMA staging 실험은 제거하고 재빌드가 적용된 candidate6와 바이트 일치함을 확인했다.

## Work Performed

### 화면 전송

- `LcdBus`가 LCD 전용 SPI2 버스/장치를 소유한다. SD의 HSPI 경로는 변경하지 않는다.
- Arduino의 64바이트 CPU 전송에서 ESP-IDF SPI DMA로 변경했다. 내부 DMA RAM 3,840 bytes의
  8줄 버퍼를 재사용하고 RGB565 바이트 순서를 패널 형식으로 바꾼다.
- LCD 작업기를 Arduino/SPI 인터럽트 코어에 두고, immutable front와 PSRAM back으로 렌더/전송을
  겹친다. 대기 프레임은 하나로 제한하며 LCD task는 interrupt DMA 완료 대기 중 양보한다.
  전송이 끝나야 front를 캔버스로 반환한다. 할당/task 생성 실패는 동기 경로로 처리한다.
- 화면 명령, 주파수 변경, 수면도 같은 전송 소유자를 사용한다. 명령/픽셀 실패는 ready와
  pending을 해제하여 실패한 프레임을 완료로 인정하거나 무한 busy로 남기지 않는다.
- 주파수·반전·수면·종료는 전송 완료를 기다린다. 모드별 forced strip 범위와 frame token은
  제출 시 snapshot한다. dirty cache는 LCD 작업기가 소유하며 영상에서 일반 UI로 전환 시 갱신한다.

### 렌더

- Claude의 기존 finishFrame 통합 변경을 보존했다.
- 정상 MEDIA는 영상이 덮는 240×240 영역의 clear와 덮어쓰는 제목을 생략한다.
- 영상 픽셀 복사·단색화·톤 보정·번인 이동을 final pass에 합친다. 무보정/무이동은
  연속 memcpy만 사용한다. UI 영역은 기존 픽셀 결과를 보존한다.
- notice/Sync stale/수면 등에서는 기존 경로를 사용하여 overlay가 영상에 덮이지 않게 한다.
- 테스트용 View.fastMedia=false는 기존 렌더를 참조로 선택한다. 실제 기본값은 true다.

### JPEG

- 기존 benchmark checkout의 JPEGDEC 1.8.4를 `lib/jpegdec`에 출처/고정 commit/LICENSE와
  함께 추가했다. RAM framebuffer만 사용하여 불필요한 bb_spi_lcd 의존 선언을 제거했다.
- MediaDecoder가 빠른 디코드를 요청하고 온라인 Artwork는 기존 경로를 유지한다.
- 입력·출력·working buffer를 16바이트 정렬한다. caller 출력이 정렬되지 않으면
  worker 소유 정렬 버퍼에 디코딩하고 결과를 복사한다. 큰 decoder 객체는 64 KiB 작업 버퍼에
  placement new하여 task stack에 두지 않는다.
- 기존 헤더 parser로 크기/출력 용량을 확인한 뒤 baseline 및 가로·세로 16의 배수에서만
  JPEGDEC framebuffer 경로를 사용한다. 지원하지 않는 크기/진행형/실패·정렬 불일치는
  기존 esp_jpeg로 처리한다. 기존 디코더가 거절하는 형식에 대한 지원을 추가했다고 주장하지 않는다.
- 검사에서 200×200 partial MCU의 framebuffer 경계 초과를 발견했다. 빠른 경로의 크기를
  제한하여 예방하고, 그 외는 기존 decoder로 처리한다.
- 벤더 portability 패치: unaligned integer load에 memcpy, Huffman table negative shift 방지,
  겹치는 parser buffer compaction에 memmove. 패치와 Apache-2.0 출처를 lib README에 기록했다.
