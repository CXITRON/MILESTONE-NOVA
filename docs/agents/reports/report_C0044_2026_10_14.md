## Title

NOVA 1.0.0의 SD 생략 복구 부팅, 반복 부팅 실패 감지, 비파괴 경로 격리와 직접 업데이트 통합

## Summary

0.1.20으로 SD 장착 재부팅 문제가 해소됐다는 사용자 확인(C0042/C0043) 후, 같은 종류의 장애에서도 설정·파일을 지우지 않고 접근할 수 있는 복구 경로를 구현했다. BACK+MENU 부팅 또는 정상 부팅 안정 전 watchdog/panic 실패 3회 뒤에는 SD를 초기화하지 않는 최소 복구 실행으로 들어간다. 휴대폰에서 설정 AP로 접속하여 SD 없이 서명 펌웨어를 전송할 수 있다.

최종 통합 1.0.0 ESP32 빌드와 전체 호스트 시험은 통과했다. 이번 코드의 실기 버튼·RTC RAM 보존·AP·직접 flash 검증은 하지 않았다. 커밋·푸시·서명·릴리스·기기 설치도 하지 않았다. 0.1.20 사용자 확인을 1.0.0 실기 검증으로 대체하지 않는다.

## Related Requests / Request Resolution

별도 U 요청의 완료 처리는 없다. 현재 직접 요청의 구현과 가능한 호스트 검증을 수행했으며 실기 확인은 남았다. NOVA의 기존 미추적·수정 문서와 U0002 이동을 보존했다.

## Work Performed / Changes

### Recovery 정책 — Codex

- 새 `src/update/Recovery.h/.cpp`: MCU RTC_NOINIT RAM에 checksum으로 보호한 실패 횟수·복구 잠금·작업 중 경로·임시 격리 경로를 둔다. NVS 쓰기와 외장 RTC 의존은 없다. 접근은 ESP32 critical section으로 직렬화한다.
- BACK+MENU를 SD 작업 전 40 ms 간격으로 두 번 확인한다. PANIC/INT_WDT/TASK_WDT/WDT에서 이전 정상 부팅이 미완료면 실패를 누적하며 3회에 복구로 전환한다. POWERON/BROWNOUT은 기록을 초기화하고 소프트 재시작은 새 실패로 세지 않는다.
- 정상 실행 60초 및 500 loop를 모두 충족하면 실패 카운트를 지운다. 복구 모드 체류는 정상 부팅 인증이나 잠금 해제가 아니다. BACK 길게·포털 정상 부팅 재시도·업데이트 성공이 명시적으로 잠금과 경로 힌트를 지운다.
- FileScope로 정상 부팅 안정 전 파일 작업의 직전 경로를 기록한다. 다음 실행의 정확한 경로 또는 하위 경로만 건너뛴다. 다른 서비스 충돌의 오탐을 줄이기 위해 안정 이후 크래시에서는 새 경로를 격리하지 않는다. 경로는 원인 후보이며 확정 진단이 아니다.

### App 복구 실행 — Codex

- `App.h/.cpp`, `AppServices.cpp`: 저장 설정을 읽되 임시 CORE·LCD 20 MHz·밝기 96·무작위 AP 암호로 최소 실행한다. 임시 설정은 저장하지 않는다.
- Storage·BLE·앨범아트·가사·Wire/외장 RTC·환경 센서·RGB LED 초기화를 생략한다. 배터리, 칩 온도, 버튼, 화면, 네트워크, 진단, Firmware/Portal만 실행한다.
- 복구에서 일반 설정/미디어/콘솔 변경을 막고 재시도·재시작·진단만 허용한다. 펌웨어 전송 중 종료/AP 닫기/다른 작업을 막는다.
- 직접 업데이트는 유효한 배터리 측정, critical 아님, thermal state < 2, 종료 요청 없음, BootConfirm pending 아님을 매 publish에서 확인한다. 시작 전 기본값은 거절이다.
- PENDING_VERIFY 이미지가 복구 화면만 실행했다고 정상 인증되지 않도록 BootConfirm tick을 호출하지 않는다. 이때 BACK 재시작으로 SDK rollback을 시도할 수 있으나 유효한 이전 슬롯이 없으면 복귀를 보장하지 않는다.

### 비파괴 SD 격리 — Codex

- `Storage.cpp`, `StorageFiles.cpp`: 설정 import·catalog·디렉토리 순회·가사·아트·미디어·file job에 경로 힌트를 적용한다. import는 SD worker 생성 전, 이후 파일 작업은 단일 worker에서 수행하여 FileScope가 중첩·경합하지 않게 한다.
- 격리 항목의 disabled는 published catalog 사본에만 적용한다. 실제 catalog_와 SD의 enabled 값은 유지한다. 격리 경로 자체가 catalog 저장 슬롯이면 다른 슬롯으로 저장하며 둘 다 격리되면 실패한다.
- 격리 스캔은 카드 catalog를 다시 쓰지 않는다. 파일 삭제·rename·포맷은 없다. 진단에는 recovery/failures/skipped를 표시한다.
- 0.1.20의 순회 양보 보완을 유지한다.

### SD 없는 서명 업데이트 — Claude Code / C0045

Firmware·Portal과 웹 포털의 직접 청크 수신을 통합했다. CRC·순서·마지막 청크 재전송·제품/버전·RSA 검증·단일 세션·취소·60초 정지·전원/온도 게이트를 처리한다. 현재 실행 이미지와 설정은 유지하지만 업로드 시작 시 비활성 슬롯의 이전 rollback 이미지는 지워질 수 있다. 실제 SDK 소스에서 서명 성공 뒤 부팅 슬롯 선택 순서를 확인했다. 상세 구현 및 독립 시험은 C0045에 있다.

복구 UI에서 미지원 조작을 숨기고 BACK 길게 재시도 안내로 수정했다. Codex는 실제 IAB에서 홈/관리를 확인했다. localhost의 상태 fixture를 사용했으며 실제 장치 API나 업로드는 실행하지 않았다.

## Issues / Limitations

- RTC RAM은 전원 완전 차단·brownout에 유지되지 않으므로 그 종류의 반복 부팅 실패는 자동 감지하지 못한다. 수동 chord가 대안이다. 실제 S3 watchdog/panic 재부팅 후 보존도 아직 미검증이다.
- NVS/기본 LCD/전원/네트워크 초기화 자체에서 실패하는 모든 상황을 복구한다고 보장하지 않는다. SD/미디어 계층을 생략하는 복구다.
- startup chord 억제 및 버튼 유지 시 의도하지 않은 OFF 발생 여부, 복구 AP 암호/화면, 실제 flash·서명 실패·취소/끊김·정상 부팅 인증·이전 슬롯 rollback은 실기 검증 대상이다.
- pending 이미지는 새 직접 설치를 거절한다. 이미 bootable 이전 슬롯이 없으면 rollback이 불가능할 수 있다.
- 1.0.0 기능은 먼저 설치돼야 쓸 수 있다. 기존 0.1.20 기기에 이 새 SD 없는 업로드 기능이 소급 적용되지 않는다.
