## Title

Sync 파일 일치·재연결, 아트·가사 갱신, 전송 실패 및 OFF 작업 종료 수정

## Summary

준비한 영상의 업로드가 실패했을 때 이전 SD 영상에 새 원본 오디오를 연결할 수 있던
Sync 경로를 수정했다. 정상 종료 후 다시 연결할 수 있도록 준비 파일을 유지하고,
연속 연결·종료 요청을 직렬 처리하며 다른 세션의 종료 요청을 거절한다.

현재 곡의 아트·가사를 포털에서 변경하면 다시 읽도록 연결했다. 변경 전 자동 조회
결과가 사용자 아트를 덮어쓰는 경로를 막고, 재조회가 실패해도 기존 정상 이미지를
유지한다. 전송 취소·브라우저 저장 실패 처리, 연속 설정 저장, OFF 시 서비스 작업과
로그 종료 대기도 수정했다.

코드 수정과 최종 빌드·호스트 검사는 2026-09-27에 수행했다. 2026-09-29에는 현재
소스·포털 자산과 해당 빌드 입력의 일치, 산출물 SHA-256을 확인하고 이 보고서를 작성했다.
이 보고서의 Completed는 해당 수정·검증 작업의 완료이며, U0001은 In Progress다.

## Work Performed

1. 브라우저 변환 결과를 IndexedDB에 쓰는 동안 전체 CRC를 누적한다. Sync 시작은
   준비 결과의 크기·CRC를 보내며, SD worker가 NJV1 형식과 정확한 크기·전체 CRC를
   확인한 뒤 연결한다. 기존 프레임 검증 과정에서 전체 CRC를 함께 계산하므로 NJV1을
   별도로 전부 다시 읽지 않는다. 프레임 CRC가 같아도 FPS 등 헤더가 다르면 거절한다.
2. SyncClock의 start/stop을 직렬 처리하고 진행 중 tick이 끝난 뒤 세션을 종료한다.
   stop에는 세션 ID를 포함한다. 활성 Sync가 없으면 화면과 로컬 재생을 바꾸지 않고
   성공하며, 다른 세션 ID는 거절한다. 정상 stop은 준비 영상을 보존하고, AP 종료·모드
   이탈 때 정리한다. 파일 준비 정보에 CRC가 없는 과거 체크포인트는 다시 준비해야 한다.
3. SD의 아트·LRC 쓰기/삭제, 보호 상태 변경, 재조회, 재탑재 성공을 revision으로
   전달한다. App은 곡 변경과 별도로 자산 generation을 갱신해 현재 곡을 다시 읽는다.
   이전 generation의 SD/Artwork 결과는 적용하지 않으며, Artwork는 오래된 결과의
   픽셀을 화면 버퍼에 복사하기 전에 폐기한다.
4. 자동 아트 조회 전에 pin/custom/block/MISSING을 검사하고, 저장 직전에도 다시
   검사한다. 포털을 열기 전에 대기하던 자동 요청이 사용자 아트나 차단 상태를 무시하지
   않도록 했다. 재조회는 기존 이미지를 선삭제하지 않고 새 정상 응답의 원자 교체를 기다린다.
5. Artwork 폼은 기존 Worker의 인코딩된 본문 1,400-byte 제한과 title/artist 필수를
   지킨다. 구분자 공간까지 계산하며 초과 metadata를 잘라서 다른 곡으로 조회하지 않는다.
   느린 응답은 읽기 반복 사이에서 15초 경과를 확인해 중단한다. 개별 HTTP 호출의
   timeout은 별도이므로 정확히 15초 이내 반환을 보장하는 실시간 제한은 아니다.
6. IndexedDB 초기화 실패를 파일 기능 오류로 처리해 포털의 설정·연결·진단 초기화는
   계속한다. request와 transaction의 실패를 함께 관찰해 처리되지 않은 Promise
   rejection을 막는다. 업로드는 begin 전 취소를 검사하고 begin에도 abort signal을
   전달하며, 범위를 벗어난 offset과 빈 chunk를 거절한다.
7. 포털 명령 적용 후 최신 snapshot을 게시하고 ACK를 보낸다. 250ms 갱신 간격보다
   빠른 연속 설정 요청이 이전 전체 설정을 기반으로 앞선 변경을 덮어쓰는 문제를 막았다.
   Sync 중 설정을 적용해도 재생 화면을 유지한다.
8. AP 서버가 닫혔다는 상태와 서비스 worker의 I/O 종료 상태를 분리했다. OFF는 새
   서비스 작업을 막고 진행 중 HTTP/Artwork 작업과 대기 로그가 끝났다는 ACK를 받은
   뒤 SD를 종료한다. NVS 저장 실패로 OFF를 취소하면 서비스와 기존 AP를 재개한다.

## Issues / Limitations

- Artwork host 검사는 HTTP transport와 시계를 대체한다. ESP TLS, 무선 지연,
  실제 SD 전기 특성, task stack 여유 및 OFF 전류는 확인하지 못했다.
- 설정 snapshot ACK, worker 중단 ACK와 NVS 실패 후 AP 재개는 실제 기기에서
  빠른 연속 입력과 I/O 경합을 포함해 확인해야 한다.
- IndexedDB를 금지한 실제 브라우저의 설정 UI, 여러 탭의 Sync, iPhone Safari/Android
  변환과 취소·재개는 이번 변경 뒤 검증하지 못했다.
- 공개 NOVA 서명 릴리스 운영, 실제 OTA slot 전환·전원 차단 복구와 장시간 운용 등
  C0002에 기록한 미검증 항목은 그대로 남아 있다.
