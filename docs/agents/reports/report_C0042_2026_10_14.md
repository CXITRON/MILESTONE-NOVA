## Title

SD 장착 부팅의 태스크 워치독 재부팅 조사와 SD 순회 양보 공백 보완

## Summary

사용자는 NOVA 0.1.18에서 microSD를 꽂고 부팅하면 재부팅이 반복되고, 빼면 멈춘다고 보고했다. USB는 연결되지 않았다. 진단 reset=6과 약 6초 간격 Boot 이력은 ESP_RST_TASK_WDT와 부합한다. SD 없는 상태는 uptime=167초, heap=138868/min=71780, SD=0/catalog=0, update_pending=0이었다. RTC 미검출은 사용자가 의도적으로 RTC를 제거한 정상 상태다.

이전 C0037 R01/C0041 B3에서 미확정 위험으로 남긴 SD 순회의 명시적 양보 공백이 0.1.18과 현재 소스에 모두 존재했다. 실제 scan handler에서 캐시 파일과 무시되는 미디어 sidecar를 순회할 때 blocking tick이 부족함을 호스트 회귀로 재현하고 보완했다. 이것은 소스 결함 확인이며 해당 기기의 재부팅 원인 확정이나 해결 확인은 아니다. 손상된 파일시스템, SD 단일 호출의 장기 blocking 등은 시리얼/카드 검사 없이 배제하지 못했다.

## Work Performed / Changes

- `src/storage/StorageFiles.cpp`: 백업 복구 순회와 catalog SD.exists 순회마다 vTaskDelay(1) 및 중단 확인. 미디어 순회의 vTaskDelay를 모든 continue 이전으로 이동해 폴더·잘못된 경로·sidecar·Sync 파일 건너뛰기에도 idle task가 실행될 기회를 보장한다. 워치독을 끄거나 타임아웃을 늘리지 않았다.
- 같은 함수에 순회 단계, 파일 방문 수, 성공 여부, 총 경과 ms를 로그로 남겨 향후 시리얼에서 어디까지 진행했는지 구분할 수 있게 했다.
- `tests/storage/test_storage.cpp`: 임시 SD에 artwork 캐시 256개와 무시되는 media sidecar 256개를 배치해 실제 FileOp::Scan handler를 실행한다. 최소 768회 양보, 빈 catalog, 두 표본 파일의 데이터 보존을 검사한다.
- 사용자 SD의 파일을 읽거나 수정하지 않았다. 포맷·삭제·기기 적용·릴리스·커밋·푸시를 하지 않았다. 기존 상대 및 사용자 변경은 보존했다.
- 사용자 자율 분담 허가에 따라 아우로라에게 diff 독립 리뷰와 USB 없는 비파괴 복구·OTA 경로 읽기 전용 조사를 요청했고 수락을 받았다(전역 codex-20261014-155010 / claude-20261014-155028). 공유 빌드 산출물은 베스퍼만 사용한다.

## Issues / Limitations / Remaining Work

- 수정 펌웨어 설치와 SD 장착 반복 부팅, 실제 순회 경과 및 워치독 안정성 확인이 남아 있다.
- 각 순회 항목마다 1 RTOS tick 대기가 추가되므로 캐시가 많으면 총 인덱싱 시간이 늘 수 있다. 영상 재생의 frame decode/전송 경로는 변경하지 않았다.
- 단일 SD 호출이 수 초 이상 막히거나 파일시스템 내부 순회가 고장난 경우 이번 양보 보완만으로 해결을 보장할 수 없다.
- OTA 다운로드는 `/update/candidate.bin`을 Storage worker로 저장하는 구조다. SD를 뺀 상태만으로 OTA 설치가 되는 것으로 안내하면 안 된다. 아우로라 복구 경로 리뷰와 사용자 적용 방식을 확인해야 한다.
- 기존 C0032의 초기 0.1.17 rollback 원인까지 이번 관측으로 확정·완료 처리하지 않는다.

## Independent Review / Follow-up

아우로라의 claude-20261014-155343을 읽었다. 아우로라는 별도 scratchpad에서 수정 전 동일 회귀 assertion 실패와 수정 후 ASan/UBSan storage 시험 통과를 직접 확인했다고 보고했다. SDK 3.3.11의 TASK_WDT_PANIC, 5초 timeout, CPU0 idle 감시와 core0/priority1 SD worker 배치를 검토했다. 이는 6초 주기와 부합하지만 실물의 WDT backtrace를 받은 것은 아니다. openNextFile의 매 항목 fopen/fstat과 FAT 탐색 비용 때문에 큰 폴더의 총 scan 시간은 양보 추가 후에도 길 수 있다.

아우로라의 시험 강화 의견을 받아 `tests/storage/support/FS.h`에 호스트 순회 관측 callback을 추가했다. 회귀는 총 양보 횟수 외에도 최대 연속 무양보 directory 방문 수가 1 이하인지 검사한다. 한 단계의 양보가 다른 단계의 누락을 보상하는 false pass를 방지한다. 강화 후 storage 시험과 diff check 재통과. 펌웨어 소스는 변하지 않아 빌드를 불필요하게 반복하지 않았다. 로컬 Nova.ino.bin SHA-256: fd4781857154d170a683d5250e7748c62eb6233a586c02082de7ad997546f91f.

복구 제안(미검증): 원래 SD를 보존하고 거의 빈 여분 SD로 부팅하여 수정 릴리스로 OTA한 뒤 원래 카드를 다시 사용한다. Wi-Fi 정보가 NVS에 있는지 확인해야 한다. 여분 카드가 없으면 카드 리더로 원본 백업 후 큰 스캔 대상 폴더를 다른 위치로 이동하는 방식이 후보지만 사용자가 카드에 접근 가능한지 아직 답을 받지 않았다. 실행 중 hot insert 후 repair는 동일 scan을 유발하므로 복구법으로 권하지 않는다. 공개 0.1.19 역시 같은 양보 공백을 가지므로 수정 포함 새 펌웨어가 필요하다.

이 수정은 서명·게시·기기 설치하지 않았다. 사용자의 설치 방식 및 해당 행위 승인, SD 장착 실물 부팅 확인이 남았다. 별개 fileJob List의 건너뛰기 경로에도 같은 유형의 공백이 있다고 아우로라가 지적했으나 부팅 경로 밖이므로 이번에 수정하지 않았다. 추가 대응 시 해당 경로도 검토한다.
