## Title

기존 사용자 기능 복원, AP Sync·미디어·Artwork·설정·업데이트 통합과 검증

## Summary

C0001에서 누락한 메뉴 프로필, 설정 AP/포털, 로컬 미디어 변환·저장·재생,
AP Sync, 기존 Artwork Worker 자동 조회·관리, 확장 설정·진단·업데이트 흐름을
실제 NOVA 모듈과 UI에 연결했다. 기존 기기의 사용자 기능을 코드 근거와 대조한
[기능 대조표](../../design/feature-parity.md)를 작성했다. 단일보드 GPIO와 현재
NOVA 디자인/온디바이스 설정을 유지한다.

이 보고서의 Completed는 아래 구현·호스트 검증 작업의 완료다. U0001 전체를
완료 처리하지 않는다. 실제 LOLIN S3 Pro/iPhone/AP/SD/OTA 동작과 장시간 운용은
검증하지 않았으며 U0001은 In Progress로 유지한다. C0001 완료 철회 기록도 유지한다.

## Work Performed

1. 기존 CORE/Video/Sync/Artwork/Portal/Network/Legacy 설정 소스 및 parity 문서를
   읽고 기능 대조표를 재작성했다. 기존 코드와 새 구현 경로, 검사 종류를 연결했다.
2. MENU에서 CORE/MEDIA/NOW를 OK 적용·BACK 취소로 전환한다. CORE 순서/mask,
   기존 화면 조합, NOW 레이아웃, 3초 splash와 12페이지 진단을 연결했다.
3. AMS Player/Queue/긴 Track 정보, Entity Attribute 읽기, 원격 명령 지원 목록을
   처리한다. GATT 상태와 지원 목록이 유효한 명령만 전송한다. 명령 write 성공을
   실제 플레이어 상태로 간주하지 않는다. metadata helper에는 제어를 허위 활성화하지 않는다.
4. SD worker가 BMP/MVJ1/MSM1 및 NVI1/NVV1/NJV1을 검증·인덱싱·재생한다.
   catalog는 CRC A/B로 경로/이름/순서/사용/표시 시간을 저장한다. 정렬, 반복,
   pause/seek, 자동 전환, 흑백 및 전역/개별 표시 시간을 적용했다.
5. 브라우저 사진/GIF/영상 변환과 IndexedDB 256 KiB chunk 보관, 재개 업로드,
   CRC 검증, SD 원자 교체를 구현했다. 체크포인트 저장 실패 때 RAM offset도
   마지막 durable 값으로 복구한다. 완성 파일 검증 전에는 기존 정상 파일을 교체하지 않는다.
6. AP Sync는 SD의 JPEG 영상과 브라우저 원본 오디오를 session/sequence/position으로
   동기화한다. 파일 식별, 늦은 tick, seek/pause, 2.5초 통신 만료, 취소/종료를 처리한다.
   catalog 갱신이 Sync 시계를 초기화하던 문제를 수정하고 모드 이탈 시 파일을 정리한다.
   SD 대기/미탑재 중에도 재생 timeout을 검사하며 자동 전환의 영상 종료 경계를 놓치지 않게 했다.
7. 기존 HTTPS Worker의 MAC1을 길이·CRC 검증 후 표시/캐시한다. 검색, 업로드 교체,
   pin/custom/block/MISSING, 재조회, metadata 검색·pagination, 한도 초과 LRU를 연결했다.
   block은 자동 조회만 억제하며 이미 저장한 사용자 아트 표시는 유지한다.
8. 설정 AP는 세션 토큰과 AP 인터페이스/Host 검사, 오프라인 자산, bounded body를
   사용한다. Wi-Fi scan/Personal/Open/PEAP 시험·성공 후 저장·8개 목록·재사용·삭제,
   AP 암호 모드, 시간/NTP, legacy schema 1..12 import, 기본값/초기화를 구현했다.
9. 환경 C/F·보정·주기·경고/위험·재검색·CSV, write-ahead journal, SD remount/복구,
   CRC 진단 이력·export/clear와 내부 온도 감속/정지·5°C 복귀 hysteresis를 연결했다.
10. NOVA manifest/HTTPS download/SHA-256/서명 후보/물리 확인 설치/A/B rollback을
    구현했다. 제품 descriptor를 MILESTONE-NOVA로 고정해 자체 이미지 검증을 통과시킨다.
    독립 release 생성 도구는 RSA-2048/4096 SDK 서명과 재검증 후 bin/manifest를 만든다.
11. UI 테마 색을 바꿀 때 실제 이미지의 동일 색상까지 바뀌던 처리를 제거했다.
    흑백은 미디어 픽셀에만 적용하며 실제 C++ renderer로 이를 검사했다.
12. [프로토콜 문서](../../guides/protocol.md#artwork-worker--캐시)에 Artwork v1/v2/v3,
    필수 폼 필드·크기·상태 코드·CORS 제약·curl/Node 사용 예·MAC1 byte layout를 정리했다.
    Worker 코드는 읽기만 했으며 서버 변경/재배포는 하지 않았다.

## Issues / Limitations

- 실제 iOS GATT 구독/명령, ESP32 HTTPS와 BLE/Wi-Fi 공존, RF 지연과 Sync 오차,
  ESP JPEG decoder/SPI/SD 제거·전원 차단, LCD/센서/전류/OFF wake,
  NVS 실패·rollback/flash 중단/24~72시간 soak는 확인하지 못했다.
- 로컬 포털 fixture의 초기 DOM과 codec 결과를 확인했다. 브라우저 제어 도구의
  입력/화면 캡처 timeout으로 전체 탭의 상호작용 검증은 끝내지 못했다.
  fixture는 실제 ESP32 WebServer나 하드웨어를 에뮬레이션하지 않는다.
- Storage host adapter는 libjpeg/호스트 파일시스템을 사용한다. 실물 SD 전기 특성,
  실제 flash/NVS 원자성, worker stack 여유 및 성능을 증명하지 않는다.
- HTTP 요청은 service worker가 직렬 처리한다. 긴 SD 파일 검증 동안 다른 HTTP
  응답이 지연될 수 있다. 물리 UI와 취소 경로는 별도이며 최대 파일/FPS는 실측해야 한다.
- 인터넷 업데이트용 공개 NOVA 릴리스와 사용자의 서명 키는 게시/생성하지 않았다.
  제공한 release 도구로 사용자가 운영하는 키와 독립 bin/manifest를 준비해야 한다.
  현재 코드가 외부에 아직 게시되지 않은 릴리스를 다운로드할 수 있다고 주장하지 않는다.
- Factory reset은 NOVA NVS만 초기화한다. SD provision 파일을 남기면 다음 부팅에
  설정/자격증명이 다시 적용된다. 손상된 로그 journal은 원본을 보존하고 실패를 알리므로
  CRC 자체를 복구할 수 없는 경우 SD 파일을 별도로 점검해야 한다.
- 아트는 곡 검색 결과이며 모든 곡의 성공/고해상도를 보장하지 않는다.
  MAC1 최대 원본은 88×88이며 NOVA의 160×160 표시는 확대 결과다.
