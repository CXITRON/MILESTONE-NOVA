## Title

LCD 위→아래 갱신 지연을 줄이기 위한 짧은 시간 단위 묶음 전송

## Summary

사용자가 LCD SPI 40 MHz에서 화면이 위에서 아래로 흘러가듯 갱신되는 현상을 보고했다.
Display::flush()가 변경된 8줄을 한 번 전송하고 반드시 반환하여 전체 화면 전환에 최대 40회
메인 루프와 양보 대기가 끼어드는 구조를 확인했다. 8줄 전송 단위를 유지하되 약 4 ms 동안
여러 묶음을 보내도록 보완하고 USB NVS 이관 준비 펌웨어를 다시 생성했다.

## Related Requests

U0001 화면 갱신 및 입력 응답성 관련 후속 제보. C0014의 128 KiB USB 준비 패키지에도 반영한다.

## Work Performed

작업 전 git status와 활성 request queue 확인. Display 및 App의 render/busy/flush 경로를 확인했다.
40 MHz는 데이터 전송 클럭이며 패널 자체의 화면 주사율이 아니다. RGB565 240×320 전체 전송은
순수 데이터만 계산해도 30.72 ms가 필요하며, 종전 방식은 각 8줄 사이에 다른 루프 처리가 추가된다.
현재 핀맵에는 TE 신호가 없고 패널과의 주사 동기화도 구현되어 있지 않다.

## Changes

- `src/display/Display.cpp`: 매번 한 묶음 후 종료하던 break를 4,000 us 경과 시 종료로 변경.
  변경 없는 묶음 생략, 전송한 프레임 복사본 비교, pending/busy 의미를 유지한다.
  프레임 전체를 무제한 blocking 전송하지 않고 메인 루프로 돌아가 입력/네트워크를 처리한다.

  글꼴 렌더링은 이 테스트 대상이 아니다.

## Issues / Limitations

4 ms는 묶음 사이에 검사하는 전송 예산이다. SPI writePixels 한 묶음, PSRAM 비교/복사,
스케줄링 지연까지 포함한 엄격한 실시간 상한은 아니다. 특히 매우 낮은 SPI 설정에서는
한 묶음 자체가 예산을 초과할 수 있다. 이 수정은 TE/vblank 동기화나 DMA 구현이 아니다.
패널의 GRAM 쓰기와 주사가 겹치는 티어링은 남을 수 있다. TE를 사용하려면 실제 모듈의
핀 노출/배선 가능 여부와 패널 타이밍을 추가 확인해야 한다.
