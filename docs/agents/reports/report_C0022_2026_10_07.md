## Title

낮은 밝기 LED의 시간 디더링·약한 감마 보정 및 느린 갱신 보호

## Summary

Claude의 `claude-20261007-230345` 인계를 읽고 밝기 상한 약 7에서 정수 단계가
드러나는 LED 효과를 개선했다. 채널별 소수 목표 밝기를 오차 누적으로 출력하고,
LED가 켜져 있을 때 최대 125 Hz로 전송한다. 실제 메인 루프가 느려지면 디더링을
중단하여 저주파 점멸을 피하도록 했다. 사용자 기본값 24와 설정 상한은 유지했다.

## Related Requests

업무 게시판의 LED 부드러운 효과 작업을 현재 사용자가 직접 진행 요청했다.
Claude는 영상 경로를 계속 맡으며 이번 작업은 그 부분을 수정하지 않았다.

## Work Performed

- 5개 LED × 3채널의 소수 오차를 독립적으로 누적해 다음 전송에 반영한다.
  채널별 초기 위상을 분산하여 모든 LED의 소수 출력이 동시에 점멸하는 경우를 줄인다.
- 효과/밝기/디더링 사용 여부가 바뀌거나 소등되면 오차를 초기화한다.
- 약한 감마 곡선 `x * (0.8 + 0.2*x)`를 사용한다. 프레임마다 pow나 동적 할당을 하지 않는다.
- Claude의 모든 채널 최소 1단계 보정을 대체했다. CORE 시계의 녹색, D-day의 빨간색만
  최소 1단계로 유지하여 밝기 6/7에서 모든 LED가 꺼지지 않는 기존 조건을 보존한다.
  보조 채널은 소수 목표값에 맞춰 출력하며 색상별 평균 밝기가 과도하게 올라가지 않게 한다.
- 켜져 있을 때 갱신 간격 8 ms. LED OFF/종료 요청에는 한 번만 즉시 소등하고 반복 전송하지 않는다.
- 실제 전송 간격이 16 ms를 넘으면 반올림 정수 출력으로 복귀한다. 16 ms 이하 갱신이
  3회 연속될 때만 디더링을 다시 사용한다. 밀린 전송을 몰아서 보내는 catch-up은 하지 않는다.
- 사용하는 효과에 필요한 sin 계산만 수행하도록 불필요한 계산을 줄였다.
- 아트 실패 1회/곡, 재시도 억제, 정상 커버 보존, 효과 우선순위는 유지했다.

## Issues / Limitations

125 Hz는 목표 최대 갱신율이며 메인 루프가 이를 보장하지 않는다. 느린 루프의 fallback에서는
정수 단계가 다시 보일 수 있다. 높은 갱신율에서도 매우 낮은 소수 밝기 또는 카메라 촬영에서
깜빡임/맥놀이가 보일 가능성은 있어 사용자 육안 확인이 필요하다.
호스트 평균 검사는 전송 프레임 평균이며, 불균일한 실제 프레임 간격의 시간 평균이나
실물 광도 측정을 대신하지 않는다. 영상 FPS/loop_max_us 전후 비교는 아직 수행하지 않았다.
