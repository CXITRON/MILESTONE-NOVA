## Title

GitHub 릴리스 업데이트(부팅·하루 한 번·수동 확인) 완성, 로컬 OTA와 암호/키 설정 제거, v0.1.1 릴리스 게시와 실기 설치 검증

## Summary

사용자가 요구한 업데이트 방식은 "GitHub 릴리스를 부팅 시와 하루 한 번 확인하고, 수동 확인과
업데이트도 가능하며, OTA 암호 같은 설정은 없어야 한다"였다. Codex가 확인·다운로드·서명 검증·설치
기반(`Firmware`, `Release`, 내장 공개키 `Trust.h`)을 만들던 중 끊겨, 그 위에 다음을 완성했다.

- 일정: 부팅 후 30초 1회, 이후 24시간마다, 실패 시 1시간 뒤 재시도. 새 버전은 **알림만** 표시하고
  설치는 사용자가 한다. 자동 설치는 선택 사항이다(기본 꺼짐).
- 로컬 Arduino OTA와 OTA 암호·공개키 프로비저닝을 모두 제거했다. 서명 검증은 펌웨어에 내장된
  공개키만 사용한다.
- 글꼴에 없는 기호(가운뎃점·줄표·화살표 등)가 `?`로 나오던 문제를 수정했다.
- `v0.1.1` 릴리스를 게시하고, 실제 기기(v0.1.0)가 이를 발견·다운로드·검증·설치·부팅 확정까지
  수행하는 것을 시리얼 로그로 확인했다.

U0001은 버튼 조작 경로, 롤백·전원 차단, 24시간 일정 관찰이 남아 In Progress로 유지한다.

## Work Performed

### 1. 로컬 OTA 제거와 부팅 확정 분리
- `src/network/Ota.*`(ArduinoOTA 수신, 암호, 공개키, 12 KiB task)를 삭제했다.
- 새 `src/update/BootConfirm.*`가 새 이미지의 60초/500회 loop/heap 확인 후 정상 확정(롤백 취소)만 맡는다.
  GitHub 설치 이미지에도 같은 확정이 필요하기 때문이다.
- 기기 설정 `Signed OTA`는 `Check update`로, console `ota`/`ota-close`와 포털 "로컬 Arduino OTA 창" 버튼과
  `OtaWindow` 명령, SD의 `ota_password`/`ota_public.pem` 읽기를 제거했다.
- `Secrets`의 `otaPassword`/`otaPublicKey` 필드는 **구조체에 남겼다**. 저장된 Wi-Fi 프로필 레코드의
  크기가 바뀌면 읽지 못하기 때문이다. 코드에서는 더 쓰지 않는다. `Firmware::begin`은 내장 키를 쓰고,
  키 덮어쓰기 인자는 시험 전용이다.

### 2. 일정(`AutoUpdate`)
- 이전: 자동 모드를 켠 경우에만 15분마다 확인하고 즉시 설치.
- 현재: 항상 확인(부팅 30초 후 1회, 24시간 주기, 실패 시 1시간). 새 버전을 찾으면 알림만 띄운다.
  자동 설치를 켠 경우에만 다운로드→설치로 이어진다. 검증된 후보(Ready)가 있으면 정기 확인이
  그것을 지우지 않도록 건너뛴다. 자동 설치를 도중에 끄면 다음 단계로 진행하지 않는다.
- 새 버전 알림은 일정/수동 확인 모두에서 한 번만 표시한다(`새 버전 vX / MENU > 업데이트`).

### 3. 업데이트 화면
- 항목을 `새 버전 확인`, `다운로드 + 서명 검증`, `이전 펌웨어로 복구` 3개로 줄였고 현재 버전을 표시한다.
  검증이 끝나면 길게 OK로 설치한다. 상태 문구를 한국어로 바꿨다.

### 4. 글꼴에 없는 기호
- 실제 글꼴(Unifont Korean2/Japanese3)로 확인한 결과 `·`(U+00B7), `—`, `–`, `→`, `°`, `…`, `•`가 둘 다 없었다.
- `Canvas::selectGlyph`에 ASCII 대체표를 추가했다(중점·줄표→`-`, 따옴표→`'`/`"`, 말줄임→`.`,
  `→`→`>` 등). 곡 제목 같은 외부 문자열에도 적용되고 저장 데이터는 바꾸지 않는다.
- 고정 문구의 `·`(온습도 대시보드 `%.1f C / %.0f %%` 포함)와 `—`, `→`도 직접 ASCII로 바꿨다.
  브라우저 포털 전용 문구 2곳은 그대로 뒀다.

### 5. 릴리스와 빌드 스크립트
- `NOVA_VERSION=x.y.z ./scripts/build/firmware.sh`가 `arduino-cli`의 따옴표 처리 때문에 실패하던
  것을 고쳤다. `-DNOVA_VERSION_NUMBER=x.y.z`(따옴표 없는 단일 토큰)를 넘기고 `Board.h`가 문자열로 만든다.
- `v0.1.1`을 빌드·서명(`release.py`)하고 `gh release create`로 게시했다.

### 6. 문서·시험
- README의 업데이트/복구 절과 릴리스 게시 절차, 설계·기능 대조·실물 점검표를 새 구조로 고쳤다.
- 시험: 부팅/일일/재시도/자동 설치 체인 일정 시험, `BootConfirm` 시험(`Ota` 시험을 대체),
  글꼴 대체 렌더 단언을 추가했다.

## Issues / Limitations

- **버튼 조작 경로 미시험:** 업데이트 화면의 OK/길게 OK는 시험하지 못했다. 자동 설치와 같은 작업기 함수를
  쓰지만 화면 조작과 문구 표시는 사람이 눌러 확인해야 한다.
- **롤백·전원 차단 미시험:** 설치 중 전원 차단, 새 이미지 비정상 시 롤백, `이전 펌웨어로 복구`는 실기에서 보지 못했다.
- **하루 주기 미관찰:** 24시간 일정은 호스트 시험으로만 검증했다. 부팅 직후 확인과 실패 시 재시도는 실기에서 봤다.
- **SD 필요:** 후보를 SD에 저장하므로 SD가 없으면 다운로드할 수 없다.
- **개인키:** `~/.config/milestone-nova/keys/nova-private.pem`(저장소 밖, 암호화되지 않은 PEM). 분실하거나
  바꾸면 이미 배포한 기기는 새 릴리스를 거절한다. 오프라인 백업이 필요하다.
- **v0.1.1 소스:** 릴리스 이미지는 커밋 `1f54005`(main)에서 빌드했다. 이후 변경은 별도 릴리스가 필요하다.
- 포털 전용 문구의 `·` 2곳(`StorageFiles.cpp`, `Network.cpp`)은 브라우저에서 정상 표시되어 바꾸지 않았다.
- C0010의 Codex 결과(일본어 글꼴, 부팅 문구, 자산 재조회, 버튼 큐)는 호스트 검사 통과만 다시 확인했다.
