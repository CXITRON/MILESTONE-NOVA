## Title

USB 연결 기기의 128 KiB NVS 이관 및 부팅 확인

## Summary

사용자가 유선 연결을 확인하고 파티션 작업 실행을 명시적으로 승인했다.
C0014/C0015에서 준비한 패키지로 기존 20 KiB에서 128 KiB로 이관했다. 첫 부팅에서 발견한
구형 Secrets 변환 스택 초과를 수정하여 앱만 다시 기록했고 정상 부팅을 확인했다.

## Related Requests

U0001의 NVS 용량/장시간 안정성 후속 작업. 실행 승인: “기기 유선연결해둠 파티션 작업 ㄱ”.

## Work Performed

- git status/request queue/공동 게시판을 읽고 기존 작업을 보존했다.
- /dev/ttyACM0의 ESP32-S3 rev0.2, USB-Serial/JTAG 장치를 확인했다.
- 준비 패키지 버전 0.1.11과 SHA-256/파티션 검사 통과.
- 초기 stub 방식 전체 읽기가 수신 오류로 중단됐다. 진행 표시를 억제해도 재현됐고,
  256 KiB 분할 읽기도 중간에 실패했다. 이 단계에서는 flash write/erase를 수행하지 않았다.
- 같은 0x80000 구간을 ROM 방식으로 읽었을 때 성공했다. 읽기 작업에 --no-stub/--no-progress를
  사용하고 전체 백업을 1 MiB씩 구성한 후 fsync 및 전체 verify-flash를 수행하도록 도구를 보완했다.
  정확한 USB/stub 내부 오류 원인은 미확정이며 물리 flash 손상으로 단정하지 않는다.

## Changes

`scripts/build/repartition.py`: ROM 경로의 bounded read 및 전체 백업 조립/길이 검사/fsync.
쓰기 및 전체 검증 조건, 원본 NVS 보존, 파티션 표 마지막 기록 정책은 유지한다.

`src/settings/Store.cpp`: 첫 부팅의 validSecretsV1/SettingsStore::load 스택 초과를 수정했다.
레거시 3,085 B 구조체를 heap에 할당하고 유효성 검사를 필드 공통 함수로 바꿔 추가 Secrets
복사본을 제거했다. 변환도 반환 임시 구조체 대신 출력 참조에 직접 복사한다. 현재 타깃 ELF의
SettingsStore::load 프레임은 0x340(832 B)로 확인했다. 저장 형식/자격증명을 변경하거나 초기화하지 않는다.

## Request Resolution

20 KiB → 128 KiB 이관 및 부팅 검증을 완료했다. U0001 전체는 In Progress 유지.
GitHub 릴리스/LED 작업은 이번 이관 작업에 포함하지 않는다. Wi-Fi 연결 문제는 아직 남아 있다.

## Verification

- 기존 준비 패키지 --inspect 통과.
- 변경한 이관 도구의 host 모의 flash 테스트 재실행.
- 전체 16 MiB 백업은 기기 flash와 verify-flash digest 일치.
- 새 앱/otadata/파티션 표 각각 기록 후 검증 통과.
- 표 전환 전에 읽어온 128 KiB NVS가 **기존 20 KiB 원본 + 확장 108 KiB의 0xff**와 정확히 일치.
- 첫 앱 부팅에서 loopTask stack canary 발생. addr2line으로 validSecretsV1 → SettingsStore::load →
  App::begin 경로를 확인했으며, 추가 재부팅을 막기 위해 다운로드 모드로 유지하고 수정했다.
- 수정 앱을 0x30000에만 다시 기록하여 hash 검증 통과. 파티션/NVS 재기록 없음.
- 수정 후 55초 부팅 로그: 0.1.11, NVS 로드, LCD 40 MHz, SD mount, RTC valid,
  기존 본딩으로 BLE encrypted(bonded=1), AMS subscribed/ready 확인. 해당 관찰 구간 panic 없음.
- 변환 저장 후 두 번째 재부팅에서도 NVS 로드, LCD 40 MHz, SD 및 UI ready 확인.
- Wi-Fi: BLE 초기화 이전 30초 연결 시도도 실패하여 Offline. BLE가 원인이라고 확정할 근거 없음.
- `./scripts/test/run.sh` 전체 통과: 코어 8612 checks, parity/portal, Python 17 tests,
  실제 storage worker. 별도 이관 테스트 5개 및 관련 release/settings 테스트 3개도 통과.
- 최종 빌드: 프로그램 1,940,350 B / 6 MiB, 정적 RAM 69,648 B. 패키지 --inspect와 diff 검사 통과.
- **Hardware Validation:** Performed — partition/byte preservation/boot/NVS load/BLE AMS scope only.

## Issues / Limitations

USB/stub 연속 읽기 실패로 여러 백업 시도가 중단됐다. 불완전한 백업은 복구 원본으로 쓰지 않는다.
이관 도중 전원 차단에 원자적인 절차는 아니며 완료된 전체 백업을 보존해야 한다.
