## Title

AP Sync·MEDIA 영상 FPS 병목 측정과 개선(화면 그리기·영상 구간 전송·재그리기 억제·화질/FPS 선택), SD 클럭 20 MHz, CORE 화면 LED 수정, 동기 연결 검증 단축, 게시판 도구와 `docs/agents` 이동

## Summary

C0012 이후의 작업을 정리한다. 사용자가 "AP Sync가 5 FPS쯤으로 보인다"고 해서 기기에 계측을 넣고 측정한 뒤,
측정에서 나온 병목을 순서대로 고쳤다.

1. 프레임 크기 맞춤(`scale565`)이 픽셀마다 64비트 나눗셈을 해서 프레임당 약 20 ms를 쓰고 있었다 → 복사로 교체.
2. 메인 루프의 `render`가 프레임당 약 100 ms였다(76,800픽셀 전체를 도는 밝기·대비 루프, 번인 방지 이동, 픽셀 단위
   영상 복사) → 값 표(LUT)·행 복사로 교체.
3. 새 영상 프레임이 없는 사이에도 같은 그림을 다시 그려 보내서 메인 루프가 포화됐다(새 프레임 6~9/s, 화면 전송
   12~14/s) → 새 프레임·화면 전환·250 ms마다만 그리도록 변경.
4. 영상 구간은 이전 프레임과 비교·복사 없이 바로 보내도록 변경, 동기 영상 화질(0.5/0.65/0.8)·FPS(20/24/30) 선택 추가.
5. SD를 20 MHz로 마운트(실패 시 10 MHz로 재시도).
6. 동기 연결 때 파일을 다시 훑던 두 번째 전체 검증을, 업로드 확정 때 기록한 내용 CRC로 대체.
7. 코어 날짜·D-day 화면의 LED가 꺼져 있던 원인(밝기 상한 6~7에서 약한 효과가 0으로 잘림)을 고치고 전용 효과 추가.

게시판 도구(`scripts/board/board.py`), `docs/codex` → `docs/agents` 이동, 휴게실·개인 메모의 로컬 전용 전환도 이번에 했다.

## Issues / Limitations

- **내가 낸 오류:** 줄 끝 `//` 주석이 같은 줄의 `signal,`을 삼켜 AP Sync 변환이 깨졌다(`node --check`는 통과). 시험으로 막았다(이전 코드로 실패를 확인).
  `mountCard()`를 `Storage.cpp`에 두어 `StorageFiles.cpp`만 빌드하는 시험이 링크에 실패한 일도 있었다(커밋 전에 발견해 옮겨서 해결).
- **JPEG 디코딩이 한계:** 프레임당 52~62 ms라 20 FPS에는 부족하다. 작업기와 메인 루프가 겹치는 구조에서 현실적인 상한은 10~12 FPS로
  추정한다(측정 전). 다음 후보: 화질 낮춤, SD 읽기와 디코딩 겹치기, 디코더 작업 공간(65 KiB)을 내부 RAM으로.
- **화질 비교는 한 가지 영상의 libjpeg 측정**(보통 크기 73%·PSNR -1.1 dB, 낮음 60%·-2.1 dB)이다. 휴대폰 브라우저 인코더는 다르다.
- **Sync 연결 단축은 업로드 이후 SD에 생긴 조용한 손상을 연결 때 못 잡는다**(재생 중 프레임 CRC가 잡음). 이전 영상은 전체 검증을 한다.
- SD 클럭 20 MHz가 이 카드에서 안정적인지는 기기 로그가 필요하다. 읽기 불안정이면 `Board.h`의 `sdHz`를 되돌린다.
- 기존 설정 레코드는 크기가 정해져 있어 설정 항목을 추가하면 저장된 설정이 초기화될 수 있다. 화질·FPS는 포털 선택값이라 설정에 넣지 않았다.
- 화면 찢어짐은 TE 핀이 없고 SPI 40 MHz가 한계라 완전히 없어지지 않는다(사용자도 기기 한계로 판단).
- 원격보다 앞선 로컬 커밋이 있고 푸시·릴리스는 하지 않았다.
