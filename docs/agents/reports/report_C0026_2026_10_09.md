## Title

MEDIA 재생·일시정지 LED 점멸 조사: RMT 보충 인터럽트 지연 가설

## Summary

사용자가 영상 재생 중 빠른 형광등 같은 깜빡임과 일시정지 중 중앙 초록색 점멸을 보고했다.
소스/설치된 NeoPixel·Arduino RMT 구현/기존 실기 로그/호스트 효과 계산을 조사했다.
가장 유력한 소프트웨어 후보는 작은 non-DMA RMT 메모리의 전송 중 보충 지연이다.
이번 LCD SPI 인터럽트와 RMT가 core1에서 경쟁할 수 있다는 근거는 있지만, 실제 파형이나
지연은 측정하지 않아 원인을 확정하지 않는다. 소스·설정·기기 변경과 업로드는 하지 않았다.

## Related Requests

U0001의 MEDIA/RGB 운용. 현재 직접 지시는 원인 조사만이며 수정 구현 권한으로 확대하지 않는다.

## Work Performed

- 작업 상태/queue 확인. LED 실행 코드 4개가 롤백 기준35a7086과 바이트 일치함을 확인했다.
- Rgb::tick은 40ms 이상 간격이며 canShow 확인 뒤 5개 픽셀 값을 넣고 show한다.
  같은 일시정지 값이어도 매번 전송한다. 125Hz 디더링은 없다.
- 정상 Paused는 양끝 청록색, 중앙3개 RGB=0이다. 고우선순위 TimerDone 등은 효과를
  가릴 수 있어 실제 순간의 상태를 기록하기 전 모든 상태 전환을 배제했다고 주장하지 않는다.
- 설치된 Adafruit_NeoPixel esp.c의 IDF5 경로: mutex, 내부 led_data, RMT_MEM_NUM_BLOCKS_1,
  10MHz 분해능, 비트별1심벌, rmtWrite blocking을 확인했다.
- 설치된 Arduino3.3.11 esp32-hal-rmt.c: with_dma=0,
  mem_block_symbols=SOC_RMT_MEM_WORDS_PER_CHANNEL*mem_size, 자동 intr_priority=0,
  copy encoder/rmt_transmit 경로 확인. S3의 채널 메모리는48심벌이며 RGB5개는120심벌이다.
  따라서 전체 프레임을 한번에 하드웨어 메모리에 담는 구성이 아니며 전송 중 보충이 필요하다.
  NeoPixel의 비트 시간은1.2us이므로 24심벌은28.8us 분량이다(계산값, 지연 실측 아님).
- LED/RMT 초기화는 App.begin의 rgb_.begin에서 수행하고 LCD SPI 버스도 setup에서 초기화한다.
  현재 main과 LCD 작업기는core1, SD/JPEG는core0. 같은 코어의 인터럽트 서비스 경쟁 가능성을 확인했다.
  LED 픽셀을 LCD task가 직접 쓰는 경로는 발견하지 못했다. pin은 RGB2/LCD6,7,15,16,17로 겹치지 않는다.
- SDK의 qio_opi config에는 RMT encoder/TX ISR handler IRAM 및 object cache-safe 설정이 켜져 있다.
  단순히 IRAM 미설정이 원인이라고 진단하지 않는다. IRAM 배치는 인터럽트 지연 자체를 없애지 않는다.
- Espressif RMT FAQ는 ISR encoding이 늦어지면 transmitter가 아직 갱신되지 않은 메모리를
  읽어 오래된 데이터를 전송할 수 있다고 설명한다. 이는 중앙에서 의도하지 않은 색상이 나오는
  증상과 맞는 기전이지만, 본 기기에서 발생했다는 증명은 아니다.
  [공식 RMT FAQ](https://docs.espressif.com/projects/esp-idf/en/v5.5/esp32s3/api-reference/peripherals/rmt.html#faq)

## Issues / Limitations

- 효과 엔진 호스트 검사는 예상 RGB 값 검증이며 실제 RMT 전송 품질을 검증하지 않는다.
- LCD/RMT IRQ 실제 priority·최대 지연·핀 파형·LED 전원/GND를 측정하지 않았다.
- 낮은 밝기 정수 단계는 웨이브의 계단 느낌을 낼 수 있으나 정상 Paused의 중앙 초록색을
  설명하지 않는다. 업데이트 간격 지연만으로 고정 RGB=0이 초록색으로 바뀐다고 보지 않는다.
- 물리적 신호/전원 문제, 순간적인 고우선순위 상태, 메모리 손상을 완전히 배제하지 못한다.
  소프트웨어 기준 RMT 보충 지연 후보가 가장 잘 맞지만 확정 진단으로 기록하지 않는다.
