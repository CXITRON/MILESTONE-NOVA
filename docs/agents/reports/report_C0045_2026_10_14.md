## Title

SD 없이 서명된 펌웨어를 비활성 OTA 슬롯에 직접 설치하는 복구 업로드

## Summary

0.1.18–0.1.20의 수동·자동 업데이트는 모두 SD의 `/update/candidate.bin`을 거친다. 그래서 SD 때문에 부팅이 망가진 기기는 SD를 빼면 업데이트할 수 없다(C0042 대응 때 확인). 이번 작업은 설정 AP 포털에서 서명 이미지를 청크 단위로 받아 SD를 거치지 않고 바로 비활성 OTA 슬롯에 쓰는 경로를 추가했다. 새 펌웨어는 RSA 서명이 확인된 뒤에만 부팅 파티션으로 선택된다.

이 경로는 두 경우에만 열린다. 하나는 베스퍼가 구현하는 복구 모드(`Firmware::recoveryMode()`)이고, 다른 하나는 정상 부팅이지만 SD가 마운트되지 않은 경우다. SD가 있는 정상 부팅은 기존 SD 후보 경로와 기기 길게 OK 확인을 그대로 쓴다.

통합 버전은 사용자 지시로 1.0.0이다(codex-20261014-174717). 이 보고서의 시험 fixture 버전은 그와 별개다. 시험은 실행 버전 "0.0.0"과 `build/firmware/Nova.ino.bin`을 임시 키로 서명한 이미지를 쓴다.

## Work Performed / Changes

`src/update/Firmware.h`, `Firmware.cpp`
- 상태: `Work::Direct`(전송 세션), `Work::DirectInstall`(워커의 서명 확인)을 추가했다.
  - Direct 세션 동안 `busy()`가 true여서 일반 OTA, 자동 업데이트, BACK 길게, 종료 요청과 겹치지 않는다.
  - `installing()`은 DirectInstall 단계에서만 true다.
  - 외부 `request()`로는 두 Work를 요청할 수 없다.
- App 제어 함수: `recoveryMode(bool)`, `directPermitted(bool)`.
  - `directPermitted`는 기본값이 false다. App이 온도, 배터리, 종료 상태를 보고 켠다.
  - 전송 중 false가 되면 다음 워커 단계, 청크, finish, end() 직전에 세션을 abort한다.
- `directBegin(id, total)` 거절 조건:
  - 워커 미준비, 게이트 닫힘, 다른 작업 중
  - 실행 슬롯이 PENDING_VERIFY인 경우
  - 크기가 1024–6291456 범위 밖인 경우
  - 실행 슬롯 상태를 알 수 없는 경우(아래)

  실행 슬롯 상태 조회 정책(베스퍼 요청, codex-20261014-175534):
  - 허용: `esp_ota_get_state_partition`이 OK이면서 PENDING_VERIFY가 아닐 때, 또는 `ESP_ERR_NOT_FOUND`(otadata가 없거나 해당 슬롯 기록 없음, USB 플래시 직후 등)나 `ESP_ERR_NOT_SUPPORTED`(OTA 슬롯이 아닌 app)일 때. pending은 otadata에만 존재하는 상태라 이 두 경우는 pending일 수 없다.
  - 거절: running partition이 NULL이거나 그 밖의 오류. 상태를 모르면 다른 슬롯을 지우지 않는다.
  - 오류 값의 의미는 SDK 헤더 `esp_ota_ops.h`(3.3.11)의 문서로 확인했다.

  통과하면 `UpdateClass` 객체와 RSA 검증기를 만들고, 서명을 설치한 뒤 `begin(total, U_FLASH)`를 호출한다.
- `directChunk`:
  - CRC가 틀리거나 offset이 어긋나면 세션은 유지한 채 거절한다. 브라우저가 다시 보낸다.
  - 응답이 유실돼 이미 기록한 마지막 청크를 다시 보내면, 다시 쓰지 않고 ok로 답한다.
  - 예고한 크기를 넘는 청크는 abort한다.
  - 첫 청크는 flash에 쓰기 전에 검사한다. ESP 이미지 magic, ESP32-S3 chip, `MILESTONE-NOVA` 프로젝트명, 버전 문자열을 확인한다. 다운그레이드는 거절하고, 같은 버전은 복구 모드에서만 허용한다.
- `directFinish`: 받은 크기가 전체와 같을 때만 DirectInstall로 넘긴다. 워커는 `updater.end()`를 호출한다. arduino-esp32 3.3.11 Updater.cpp에서 서명 검증(819행)이 `_verifyEnd`의 `esp_ota_set_boot_partition`(735행)보다 먼저 실행되는 것을 소스로 확인했다.
- 실패 처리:
  - 대상: 서명 거절, 쓰기 실패, 취소, 60초 무청크, 게이트 닫힘
  - 처리: 모두 `updater.abort()`를 거쳐 State::Failed가 되고, 실행 중인 이미지와 NVS는 건드리지 않는다.
  - 비활성 슬롯에 남아 있던 이전 이미지(롤백용)는 지워질 수 있다. 화면 안내에서도 이 점을 따로 밝혔다.
- 기존 `prepare()`의 헤더 검사는 공용 함수 `novaImage()`로 뽑아 냈고, 동작은 그대로다.
