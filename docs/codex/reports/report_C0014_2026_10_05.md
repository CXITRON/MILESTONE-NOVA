## Title

USB 연결 후 실행할 128 KiB NVS 이관 패키지 및 검증 절차 준비

## Summary

사용자가 128 KiB 권고를 받아들여 집에서 USB 연결 후 바로 이관할 수 있게 준비하도록 요청했다.
파티션 표, 오프라인 준비 패키지, 배치 검사·전체 백업·보존 검증을 갖춘 USB 전용 이관 도구를
준비했다. 기기는 현재 연결되지 않았으며 실제 플래시 쓰기나 GitHub 배포는 수행하지 않았다.

## Related Requests

U0001의 NVS 안정성 후속 작업. 앞선 C0013의 설정 저장/Wi-Fi 보완을 포함한 현재 소스로 빌드했다.

## Work Performed

- 작업 전 git status와 request queue를 확인하고 기존 Claude 문서 및 C0013 소스 변경을 보존했다.
- 기존 USB 스크립트는 기기 배치 확인 없이 20 KiB NVS만 백업하고 고정 영역을 지웠다. 실제
  배치를 검사하고 전체 플래시 백업을 기기와 대조하도록 보완했다.
- 기존 20 KiB 및 선행 64 KiB NOVA 배치에서만 실행되며, 이미 128 KiB 또는 다른 배치는 거절한다.
- ESP32-S3만 허용하고 암호화/보호 우회 옵션이나 전체 지우기 명령은 사용하지 않는다.

## Changes

- `partitions.csv`: NVS `0x9000 + 0x20000`, otadata `0x29000 + 0x2000`,
  app0 `0x30000 + 0x600000`, app1 `0x630000 + 0x600000`. 두 앱은 기존처럼 각 6 MiB이고
  마지막 주소는 `0xC30000`으로 16 MiB 플래시 안에 들어간다.
- `scripts/build/repartition.sh`: `--check`로 빌드·준비, `--inspect`로 무결성 검사,
  `/dev/...` 인자로 준비 패키지를 USB 적용한다. USB 적용 시 재빌드/인터넷 접속이 필요 없다.
- `scripts/build/repartition.py`: 파티션 MD5·타입·위치·크기·flags 검사, NOVA/S3 앱 descriptor·버전·크기
  검사, SHA-256 패키지 고정 및 작업별 payload snapshot, 16 MiB 전체 백업·verify-flash,
  기존 NVS 별도 추출, 명시적 MIGRATE 확인, 단계별 쓰기 검증을 담당한다.
- 새 앱 검증 후 확장 영역을 지우고 새 otadata를 기록한다. 기존 NVS prefix가 그대로이고 확장
  페이지가 모두 0xff인지 읽어서 확인한 뒤 **파티션 표를 마지막에 기록**한다.
- 모든 esptool 단계는 `--after no-reset`이며 자동 앱 재부팅/자동 재시도를 하지 않는다.
  성공 후 USB 재연결로 부팅한다. 백업은 `build/repartition/usb-*/` 아래 소유자 전용 권한이다.
- `README.md`: 준비/실행/중단/복구 및 USB와 앱 OTA의 차이를 문서화했다.
- `tests/test_repartition.py`: 실제 Python 이관 코드를 바이트 주소 기반 모의 플래시에 실행한다.

앞서 보류된 GitHub 릴리스와 LED 구현은 이번 준비 작업에 포함하지 않았다.

## Issues / Limitations

- 호스트 모의 플래시는 실제 USB 재열거, 플래시 전원 차단, NVS GC 또는 기기 부팅을 재현하지 않는다.
- 표를 마지막에 쓰더라도 새 앱 기록 시 기존 앱 일부를 덮으므로 이관은 전원 차단에 원자적이지 않다.
  중간 실패 시 다운로드 모드에서 전체 백업으로 복구해야 한다. 따라서 백업 검증을 쓰기 전에 강제한다.
- 전체 백업에는 비밀번호/본딩 키가 포함된다. 저장소의 build ignore 안에 소유자 전용으로 보관하며
  업로드하지 않는다. 복구 시 해당 백업과 동일한 기기인지 확인해야 한다.
- NVS 원본 보존은 플래시 단계에서 검사한다. 이후 앱 부팅 시 설정 자동 마이그레이션까지 포함한
  실제 보존 여부는 USB 연결 후 검사해야 한다.
